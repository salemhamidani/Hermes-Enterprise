## Version Pinning Decision

HES must not use `latest` or `main` for production Hermes services.

Recommended future production pin:

```text
nousresearch/hermes-agent:v2026.7.7.2@sha256:9c841866021c54c4596849f6135717e8a4d52ba510b7f52c50aef1de1a283973
```

The exact digest must be revalidated during the future implementation sprint before it is placed in `.env.example` or Compose files.

## Key Findings

- Upstream Hermes Agent has a Dockerfile and Docker workflow that publish multi-arch images to Docker Hub.
- Upstream Compose starts `gateway` and `dashboard` from the same image.
- Upstream Compose uses `container_name` and `network_mode: host`, which are not HES-compliant.
- The upstream dashboard warns against unsafe remote exposure and defaults to localhost behavior.
- No official LTS channel was verified.
- Release tags use CalVer, while the package version uses SemVer.
